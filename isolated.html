Architecture B — isolated solo

Each DGX Spark runs its own vLLM at TP=1. No Ray. No shared OpenAI listener. Application stacks stay separate. Documentation names: node-a (personal apps + Hermes) and node-b (workload UI). Addresses in examples are TEST-NET only (192.0.2.0/24, 198.51.100.0/30).

Layout

node-a                              node-b
Open WebUI :8080                    Open WebUI :8080
Hermes :9119                        n8n :5678
 n8n :5678
        \                                   \
         vLLM :8000 TP=1                     vLLM :8000 TP=1
         example 27B-class FP8               example 122B-class INT4

Launch

cd "$HOME/spark-vllm-docker"
./run-recipe.sh RECIPE --solo -d --tp 1 -- \
  --served-model-name SERVED_ID \
  --max-model-len CONTEXT_CAP
  • 122B-class FP8 recipes marked cluster_only cannot be the solo recipe. Use INT4 AutoRound or a 27B/35B FP8 recipe.
  • Cap context on the first window (32768 on the large INT4 lane; 65536 on a 27B lane if the agent requires ≥64k).
  • Qwen3.5 tool loops: --tool-call-parser qwen3_coder.
  • Open WebUI: --add-host=host.docker.internal:host-gateway, Connections http://host.docker.internal:8000/v1.
  • Port 8000 stays off every overlay network.

Units

See templates/vllm-solo.service and templates/vllm-cluster.service. Disable the cluster unit on boot before leaving a node in solo mode. Both layouts use the container name vllm_node — remove it when switching.

Switch A → B

  1. Stop the cluster from the head. docker rm -f vllm_node on both nodes.
  2. Disable the cluster unit on boot.
  3. Launch solo on each node. Install the solo unit if you want autostart.
  4. Point each Open WebUI at its own :8000.
